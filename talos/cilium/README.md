# Cilium (CNI bootstrap)

[Cilium](https://cilium.io) replaces both Flannel and `kube-proxy` for this
cluster. Because Talos boots without any CNI, Cilium has to be present *before*
the API server is reachable for normal Helm installs — so the chart is rendered
into the Talos machine config as an inline manifest at bootstrap time.

### Files

- `values.yaml` — Helm values (kube-proxy replacement on, Gateway API on,
  agent/operator/Hubble metrics on, and the Talos-specific cgroup/security
  knobs).
- `patch.yaml` — header that disables Talos's built-in kube-proxy and opens an
  `inlineManifests[].contents` block. The renderer indents the Helm output
  underneath it.
- `manifest.gen.yaml` — generated, gitignored, regenerated by
  `just render-cilium` (or implicitly by `just genconfig`).

### Observability

Four metrics endpoints: the agent on 9962, the operator on 9963, Envoy on 9964,
and the Hubble flow exporter on 9965. Their `VMServiceScrape`s live in
[`k8s/infra/configs/cilium/`](../../k8s/infra/configs/cilium/) and are applied
by Flux — the chart's own ServiceMonitors are unusable here because Talos
applies this manifest before any CRD exists.

Hubble Relay and the UI are deliberately not deployed. Nothing dials the Hubble
gRPC API as a result, so `hubble.listenAddress` is closed and its TLS disabled,
which is also what removes the cert CronJob and keeps generated key material
out of the machine config. Flow *metrics* are unaffected — they come off the
agent on 9965 and do not involve Relay.

Note that `dns` and `http` Hubble metrics need L7 parsing from a
CiliumNetworkPolicy. There are none in this cluster, so both were enabled and
silently emitted nothing; do not re-add them without an L7 policy.
